# Правила для AI-агента

Проект: Java 17 / Maven / JUnit 5. Демо к докладу «AI-native тестирование» (AI BOOST '26).
Архитектура: [architecture_java.md](architecture_java.md).

## 1. Оракул = спецификация

- Ожидаемое поведение берётся **только** из `openspec/specs/**/spec.md` (и из дельт в `openspec/changes/**/specs/`, если задача про изменение).
- Исходный код в `src/main/java` можно читать только чтобы узнать сигнатуры, типы и точки подключения. Ожидаемые значения из реализации **не выводить**: тест, написанный по коду, закрепляет баги кода.
- Ожидаемый результат в тесте берётся из строки `THEN` сценария. `GIVEN` превращается в подготовку данных, `WHEN` в вызов.

## 2. Связь теста со сценарием

- Каждый тест из спеки лежит в `src/test/java/demo/fromspec/` и помечен `@Tag("<ID сценария>")`, например `@Tag("TXT-EQ-01")`.
- Один сценарий = минимум один тест. В `@DisplayName` дублируется заголовок сценария.
- Тег `from-code` зарезервирован для антипримера в `src/test/java/demo/fromcode/`. В `fromspec/` его не использовать.
- Покрытие требований считает `scripts/req_coverage.py` по этим тегам; сценарий без теста блокирует CI.

## 3. Неоднозначность: стоп и вопрос

Если сценарий допускает больше одного толкования (нет чисел, единиц, границ; слова вроде «some», «usually», «a while», «быстро»), **не пиши тест и не угадывай**. Остановись и задай человеку вопрос: что именно не определено и какие варианты ты видишь. Продолжай только после того, как человек поправит спеку.

## 4. Границы ответственности

- Спеки пишет и меняет человек. Агент может предложить дельту в `openspec/changes/`, но не правит `openspec/specs/` молча.
- Агент **не отмечает** пункты чеклиста ревью в PR (`.github/pull_request_template.md`). Их принимает человек.
- Не ослабляй гейты: не понижай `mutationThreshold`, не исключай классы из PIT и JaCoCo, не добавляй `@Disabled`, чтобы сборка позеленела.

## 5. Команды

```bash
openspec validate --all --strict --no-interactive   # Gate 1
mvn -B test                                         # тесты из спеки
mvn -B test-compile org.pitest:pitest-maven:mutationCoverage   # Gate 2
python3 scripts/req_coverage.py --min 100           # покрытие требований
mvn -B test -Pdemo-from-code                        # антипример (только демо)
```
